= chora-registry — Quick Start for Platform Maintainers
:toc:

== Overview

This guide covers packaging, deploying, and maintaining chora-registry for
distribution on your platform.

== Runtime Dependencies

Node toolchain (worker/), VeriSimDB

== Build from Source

[source,bash]
----
git clone https://github.com/hyperpolymath/chora-registry.git
cd chora-registry
just build-release
----

Output: `worker/ (no compiled artifact; deployed via wrangler)`

== Packaging

=== Guix

[source,bash]
----
guix build -f guix.scm
----

=== Nix

[source,bash]
----
nix build
----

=== Container (Stapeln)

[source,bash]
----
just stapeln-export    # Generates Containerfile
podman build -t chora-registry .
----

=== Manual Package

[source,bash]
----
just install --prefix=/usr/local
----

Files installed:

[cols="1,2"]
|===
| Path | Contents

| `$PREFIX/bin/`
| Executables

| `$PREFIX/share/chora-registry/`
| Data files, assets

| `$PREFIX/share/doc/chora-registry/`
| Documentation

| `$PREFIX/share/applications/`
| .desktop file (Linux, if GUI)

| `$PREFIX/share/man/man1/`
| Man pages
|===

== Configuration

No code reads a `chora-registry/config.toml` file. The only settings file read
is `${XDG_CONFIG_HOME:-$HOME/.config}/rsr/defaults`, by the `just init` and
`just container-init` recipes. It is a shell file of `KEY=value` lines. Only
some prompts use it: `OWNER`, `AUTHOR`, `AUTHOR_EMAIL`, `AUTHOR_ORG`,
`AUTHOR_EMAIL_ALT` and `FORGE` in `just init`, and `OWNER` (for the registry)
in `just container-init`. The service name and port prompts do not.

== Multi-Instance Deployment

For deploying multiple instances (e.g., different users or tenants):

[source,bash]
----
just install --prefix=/opt/chora-registry-instance1 --config=/etc/chora-registry/instance1.toml
just install --prefix=/opt/chora-registry-instance2 --config=/etc/chora-registry/instance2.toml
----

Each instance has isolated config, data, and logs.
